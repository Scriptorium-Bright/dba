# 운영 실습 기록 연결

이 문서는 운영 변경과 개발 실험을 재현할 때 필요한 산출물 연결 방식을 정합니다. 실행 절차는 `implementation/phase-guide.md`, 실제 변경과 수치는 `implementation/exec/` 및 `experiments/results/`에서 관리합니다.

## 실행 기록 항목

각 재현 결과는 다음 정보를 함께 기록합니다.

| 항목 | 기록 내용 |
|---|---|
| 환경 | Compose project, 컨테이너, DB 이름, PostgreSQL/application 버전, 포트 |
| 초기 상태 | migration 버전, 행 수, 관련 wallet/grant/ledger 값, active sessions |
| 실행 | exact API request, SQL, 스크립트 인자와 시각 |
| 관측 | API status/body, Hikari metric, PostgreSQL state/wait event, query plan |
| 변경 | DDL·procedure·configuration, 적용 계정과 transaction 여부 |
| 결과 | schema history, catalog flags, 지급 건수, wallet/ledger 대사, 반환 행 |
| 정리 | scratch object, test row, disposable DB와 volume 처리 |

## 현재 실습 기록

| 주제 | 실행 기록 | 원본 근거 |
|---|---|---|
| 동시 지급과 Crash Recovery | [P2a](implementation/exec/p2a.md), [P2b](implementation/exec/p2b.md) | `experiments/results/`와 P2 acceptance JSON |
| 장애 보상과 schema 배포 | [P3](implementation/exec/p3.md) | Flyway 이력, constraint catalog, 구버전 API response |
| 100만 건 지급 이력 검색 | [P4](implementation/exec/p4.md) | EXPLAIN, buffers, index catalog, WAL 비교 |
| Lock Wait와 API 지연 원인 | [P5](implementation/exec/p5.md) | client 표본, Hikari metric, `pg_stat_activity`, blocker chain |
| Flyway concurrent index 복구 | [P4 V15 복구](implementation/exec/p4.md#v15-실패-이력-복구-재현) | failed schema history, index definitions, repair 뒤 success |

## 운영 변경 기록

DDL·권한·인덱스 변경은 migration version, 실행 계정, transaction 방식, 예상 lock, 검증 SQL, rollback·forward-fix 절차를 함께 작성합니다. 데이터 변경은 적용 전후의 업무 건수와 wallet·ledger 대사를 같은 실행 기록에 둡니다.

실험 자료의 파일 설명과 재실행 명령은 [`experiments/README.md`](../experiments/README.md)에 있습니다.
