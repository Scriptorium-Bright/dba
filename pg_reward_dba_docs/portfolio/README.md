# 펄어비스 DBA 지원 포트폴리오 초안

## 프로젝트 소개

**PostgreSQL 기반 게임 이벤트 보상 DB 운영 실습**입니다. 이벤트 보상의 지급 사실, 현재 지갑 잔액, 잔액 변동 원장을 설계하고, 동시 지급·작업 중단·장애 보상·스키마 변경·대량 조회·Lock Wait 상황을 단계별로 재현해 결과를 확인했습니다.

Docker Compose의 PostgreSQL 17.12와 Spring Boot API, React 화면을 사용했습니다. DB 변경은 Flyway migration으로 버전 관리하고, 지급 결과는 API 응답과 grant·wallet·ledger 데이터로 나눠 대조했습니다.

## 포트폴리오에서 보여줄 핵심 판단

1. 지급 사실, 현재 잔액, 변동 이력을 각각 관리해 지급 결과와 잔액 근거를 대사할 수 있게 했습니다.
2. 중복 방지는 API의 사전 조회만으로 처리하지 않고 DB UNIQUE 제약과 트랜잭션으로 보장했습니다.
3. 대량 작업의 완료 여부는 작업 로그 카운터가 아닌 실제 지급 행과 원장 대사로 확인했습니다.
4. 스키마 변경을 확장·제약 추가·과거 데이터 검증·호환성 확인 단계로 나눠 실패를 복구했습니다.
5. 조회 튜닝은 데이터 비율, 실행계획, buffer, 인덱스 크기, WAL과 DDL 대기를 함께 살폈습니다.
6. Lock 장애는 waiter만 보지 않고 blocker의 SQL·세션 상태·트랜잭션을 찾아 복구 여부까지 확인했습니다.

## 제출용으로 다듬을 프로젝트 요약

> PostgreSQL 기반 게임 이벤트 보상 DB 운영 실습을 진행했습니다. 지급 사실·지갑 잔액·변동 원장을 분리 설계하고, 프로시저와 제약 조건으로 동시 지급의 정합성을 확인했습니다. 1,000명 지급 작업 중단 후 미지급 대상을 재처리해 grant 1,000건과 원장 대사를 확인했고, 장애 보상과 단계별 migration, 100만 건 원장 조회 튜닝, Lock Wait 진단까지 재현했습니다. 각 변경은 실행 계획·응답·DB 데이터·대사 결과를 기록해 재검토할 수 있게 정리했습니다.
