# 직무요건과 프로젝트 증거 매핑

공고의 업무와 역량을 프로젝트에서 직접 확인할 수 있는 산출물에 연결했습니다. 각 설명은 PostgreSQL 실습에서 확인한 범위에 맞췄습니다.

| 프로시저 개발 | [P2 지급 프로시저와 트랜잭션](phases/P2_프로시저와_트랜잭션.md), V3 | CLAIM과 BATCH가 공용 지급 규칙을 사용하고, 지급·잔액·ledger가 같은 트랜잭션에 반영되는 흐름을 설명합니다. |

## 필수 역량

| 요구 역량 | 근거 |
|---|---|
| RDBMS 기본 이해와 SQL 활용 | 정규화한 관계 모델, 제약 조건, 트랜잭션, SQL 프로시저, JOIN, 실행계획, 대사 쿼리로 연결합니다. [P0–P1](phases/P0-P1_기반설계와_스키마.md), [P2](phases/P2_프로시저와_트랜잭션.md), [P4](phases/P4_쿼리와_인덱스_튜닝.md) |
| 문제 해결 능력 | 관측한 문제를 데이터·세션·계획으로 분리하고, 가설을 검증한 다음 같은 기준으로 결과를 재확인했습니다. P2 rollback, P3 migration 복구, P4 계획 비교, P5 Lock Wait가 사례입니다. |
| 원활한 소통 능력 | 실행 전 계획, 실행 단계, 결과, 결정 이유, 재실행 경로를 문서화했습니다. [구현 전 계획](../implementation/plan.md)과 [구현 후 기록](../implementation/exec.md)을 함께 보여줍니다. |

## 포트폴리오에 넣을 핵심 지표

| 사례 | 확인한 수치 |
|---|---|
| 동시 CLAIM | 같은 사용자·이벤트·요청 ID의 100개 요청에서 `PAID=1`, `REPLAYED=99` |
| BATCH 중단 후 재개 | 최종 대상 1,000명, grant 1,000건, 미지급 0명, grant·wallet 대사 불일치 각각 0 |
| 보상 원장 조회 | 100만 건 중 EVENT 990,000건, COMPENSATION 10,000건; 두 최종 부분 인덱스 각 672KB |
| Lock Wait | waiter PID 529에서 blocker PID 507을 확인; 조치 후 UPDATE 완료와 fixture 복구 |

수치에는 해당 실습 조건과 phase 실행 문서를 함께 제시합니다. 실행 시간은 환경·cache 상태에 따라 차이가 있어 반복 관측값과 실행계획을 같이 설명합니다.

## 지원자가 직접 채울 항목

- 지원 동기와 본인의 학습·협업 경험
- 실제 플레이한 게임, 플레이 기간, 게임 서비스에서 관심 있게 본 운영 요소
- 프로젝트 중 본인이 맡은 범위와 사용한 도구에 대한 본인의 설명

개인 경험 항목은 확인 가능한 사실을 기준으로 작성합니다.
