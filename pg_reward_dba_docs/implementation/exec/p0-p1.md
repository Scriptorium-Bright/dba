# P0~P1 실행 기록 — 기본 환경과 이벤트 지급 화면

P0는 PostgreSQL·애플리케이션·migration 실행 기반을 만들고, P1은 사용자와 운영자의 이벤트 업무 흐름을 연결합니다. P2는 같은 지급 계약을 공용 PostgreSQL procedure로 옮겨 동시성과 복구 시나리오의 기준으로 사용합니다.

## 추가·변경 파일

| 파일 | 내용 | 주석과 설계 이유 |
|---|---|---|
| `compose.yaml`, `.env.example`, `.gitignore`, `.dockerignore` | 로컬 PostgreSQL/API 실행, 환경 변수, 개발 산출물 제외 | 포트·volume과 DB 계정 설정을 명시해 데이터 경계와 실행 구성을 한 곳에서 확인합니다. secret은 환경 변수로 전달합니다. |
| `database/bootstrap/10-create-roles.sh` | `reward_app`, `reward_migration`, `reward_observer` 역할 준비 | 앱 DML, schema migration, 관측 권한을 나눠 역할별 작업을 구분합니다. SQL 주석은 권한 목적을 설명합니다. |
| `database/migrations/V1__create_reward_schema.sql` | 사용자·지갑·이벤트·대상자·지급·원장·감사·배치 테이블 | PK/FK/UNIQUE/CHECK와 업무 조회 인덱스를 정의해 초기 정합성 규칙을 DB schema에 둡니다. |
| `database/migrations/V2__seed_demo_data.sql` | 데모 사용자, CLAIM 이벤트, BATCH 대상 fixture | 사용자가 화면에서 조회할 수 있는 기준 데이터를 구성합니다. |
| `backend/` Spring Boot API | 이벤트·지갑·수령·운영자 상태 변경, 트랜잭션 경계, Actuator health | 초기 CLAIM 경로는 Spring transaction에서 grant·wallet·ledger를 함께 갱신했고, P2에서 공용 procedure 호출로 정리했습니다. |
| `frontend/` React + Vite 화면 | 이벤트 목록·상세, 내 지갑·원장, 역할 전환, 운영자 이벤트 생성·상태 관리 | 개발용 사용자·역할 전환과 로컬 API proxy를 코드 주석으로 설명합니다. |
| `README.md`, `pg_reward_dba_docs/00_README.md` | 로컬 실행, 포트, 운영·개발 문서 위치 | 프로젝트 실행을 재현하고 현재 실습 안내로 이동할 수 있게 시작 경로를 제공합니다. |

## 주요 설계 판단

- 앱 계정과 migration 계정을 분리해 API 런타임 역할에 DDL 권한을 주지 않았습니다.
- `reward_grants`는 지급 사실, `wallets`는 현재 잔액, `wallet_ledger`는 재화별 변경 근거를 나타냅니다.
- `event_status_audit`와 `event_policy_audit`를 업무 데이터와 분리해 상태 전이와 지급 정책 변경을 보존합니다.
- CLAIM/BATCH를 `events.mode`로 구분하고 같은 지급 규칙과 원장 모델을 공유합니다.
- 서비스 포트는 loopback에 바인딩해 로컬 실습 흐름을 구성합니다.

## 실행 환경과 확인값

최초 P0/P1 환경은 PostgreSQL 17.12, Java 21, Spring Boot 3.5.16, React 19.3.1, Vite 8.3.8을 사용했습니다. PostgreSQL health, Flyway 초기 migration, API health, 프런트 HTTP 응답, `/api/events` 응답을 확인했습니다.

| 서비스 | 주소 | 목적 |
|---|---|---|
| Frontend | `http://127.0.0.1:5174` | 이벤트·지갑 화면 |
| API | `http://127.0.0.1:8082` | 화면 요청과 지급 API |
| PostgreSQL | `127.0.0.1:5432` | `rewarddb` 로컬 실습 DB |

기본 포트가 사용 중이면 Compose 설정으로 다른 로컬 포트를 지정합니다. 관리형 Colima에서 프런트 포트 포워딩과 같은 Docker daemon을 쓸 때는 [Phase 안내서](../phase-guide.md)의 `DOCKER_HOST` 설정을 따릅니다.
