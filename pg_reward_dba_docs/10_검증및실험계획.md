# 10. 검증 및 실험 계획

## 1. 공통 원칙

- 테스트마다 `TC-ID`, 관련 요구사항 ID, 초기 DB 상태, SQL/API 입력, DB 최종 상태, 기대 결과, 실제 결과를 남긴다.
- 단위/통합/DBA 실험을 구분한다.
- 시간·처리량·복구 수치는 실행 결과 파일에 조건·반복 회차와 함께 기록한다.
- 성능·장애 실험은 동일 데이터량/분포·부하·설정에서 최소 3회 반복한다.
- 테스트 결과 분류는 **신규 지급(커밋 확정), 기존 지급, 거부, 예외, 결과 미확정**을 구별한다.

## 4. 검증 SQL

```sql
-- 이벤트 대상 대비 미지급자
SELECT r.user_id
FROM event_recipients AS r
LEFT JOIN reward_grants AS g
  ON g.event_id = r.event_id AND g.user_id = r.user_id
WHERE r.event_id = 2 AND g.id IS NULL
ORDER BY r.user_id;

-- 동일 이벤트 중복 지급 (정상: 0행)
SELECT event_id, user_id, COUNT(*)
FROM reward_grants
GROUP BY event_id, user_id
HAVING COUNT(*) > 1;

-- 지급액과 원장 합계 불일치 (정상: 0행)
SELECT g.id, g.money_awarded, g.points_awarded
FROM reward_grants g
LEFT JOIN wallet_ledger l ON l.reward_grant_id = g.id
GROUP BY g.id, g.money_awarded, g.points_awarded
HAVING g.money_awarded <> COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='MONEY'),0)
    OR g.points_awarded <> COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='POINT'),0);

-- P2: 초기 잔액 0/차감 없음 가정 시 지갑과 원장 합계 비교
SELECT w.user_id, w.money_balance, w.point_balance,
       COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='MONEY'),0) AS ledger_money,
       COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='POINT'),0) AS ledger_point
FROM wallets w
LEFT JOIN wallet_ledger l ON l.user_id = w.user_id
GROUP BY w.user_id, w.money_balance, w.point_balance
HAVING w.money_balance <> COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='MONEY'),0)
    OR w.point_balance <> COALESCE(SUM(l.amount) FILTER (WHERE l.currency_type='POINT'),0);
```

## 5. Crash Recovery와 미지급 재처리의 측정 분리

- **DB Crash Recovery 기간:** DB 프로세스 재시작부터 정상 쿼리를 받을 수 있는 시점까지.
- **업무 Recovery 기간:** 복구된 DB를 기준으로 미지급자를 식별하고 마지막 대상자까지 처리하는 데 걸린 시간.
- **요청 결과:** 외부에서 성공 응답을 관측한 요청과 DB에 실제 남은 기록을 대조.
- **HA 실험 RTO:** 장애 발생부터 첫 정상 쓰기 성공까지(측정 기준 고정).
- **HA 실험 RPO:** 장애 전 확인된 성공·커밋 기록 중 전환 후 DB에서 잃은 기록의 시간 범위/건수(정의 명시).
