# 14. 용어집과 공식 참고 문서

## 1. 개념·용어

| 용어 | 이 프로젝트에서의 의미 |
|---|---|
| SP (Stored Procedure) | DB에 저장된 호출 가능한 절차. PostgreSQL은 `CREATE PROCEDURE` + `CALL` |
| Function | PostgreSQL 함수. SQL·데이터 변경도 가능; `SELECT func(...)` 등으로 호출 |
| `RETURNING id` | INSERT 등의 결과로 실제 영향 행의 ID 반환; PL/pgSQL에서는 `INTO 변수` 저장 |
| Transaction | COMMIT 또는 ROLLBACK되는 원자적 작업 단위 |
| Idempotency | 같은 업무 요청을 다시 수행해도 지급이 추가 발생하지 않게 하는 성질 |
| UNIQUE constraint | `(event_id,user_id)`의 중복 지급 불변조건을 DB 레벨에서 보호 |
| WAL | 장애 복구와 복제에 사용되는 Write-Ahead Log |
| CHECKPOINT | 데이터 페이지 기록과 WAL REDO 시작 지점을 연결하는 복구 기준 |
| Crash Recovery | 비정상 종료 후 WAL 기반 일관된 DB 상태 복원 |
| Business retry | 복구된 지급 테이블과 대상자 목록을 비교해 미지급 업무 재처리 |
| Primary / Standby | PostgreSQL 쓰기 서버 / 변경사항을 따라가는 복제 서버 |
| Failover | 장애 시 Standby를 새 Primary로 전환하고 연결을 이동 |
| RTO / RPO | 목표 복구시간 / 허용 데이터 손실량의 시간 기준. 실험에서는 관측된 값과 목표를 구분 |
| PITR | Base Backup + WAL로 과거 특정 시점의 DB를 복원 |
| Lock Wait | 다른 트랜잭션/DDL의 잠금 때문에 대기 |
| `CREATE INDEX CONCURRENTLY` | 인덱스 구축 중 일반 쓰기를 허용하는 PostgreSQL 방식. 트랜잭션 블록 내 실행 불가 |
| Read-after-write | 쓰기 완료 직후의 후속 읽기가 해당 변경을 확인해야 하는 일관성 요구 |
| Delta Debugging | 특정 입력이 재현 가능한 오류를 일으킬 때 원인 입력을 축소해 찾는 접근 |
| Parametric Search | 단조 판정함수 등 조건을 만족하는 임곗값을 탐색하는 접근. DB 처리량의 단조성은 가정하지 않음 |

## 4. 적용 전 확인사항

- 이 문서 집합은 PostgreSQL **17**을 기준안으로 잡았다. 실제 이미지의 **정확한 마이너 버전**을 P0에서 고정하고 SQL을 실행 검증한다.
- 도구별 최신 기능과 버전 호환성은 실제 구현 시 재확인한다.
- 문서 내 샘플 SQL은 개념 명세와 실험용 예시를 포함한다. 실측 결과로 제시하지 않는다.
